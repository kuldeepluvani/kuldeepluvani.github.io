The Harness · Chapter 0

Agent = Model + Harness

The same weights score differently depending on what wraps them. That wrapper has a name, a short history, and a large share of the blame when agent projects fail.

~9 MIN READ1 LIVE INSTRUMENT

Run Claude Fable 5 inside Claude Code and it solves 83.8% of Terminal-Bench 2.1. Run the identical weights inside Terminus 2 and it solves 80.4%. Gemini 3 Pro goes the other way: 73.9% in Terminus 2, 65.8% in Gemini CLI, its own vendor's tool.1 Nobody retrained anything between those runs. The model file is the same. What changed is the software around it, and that software is the subject of this book.

Same weights, different scores

The gap is real, it repeats across benchmarks, and in controlled studies it is larger than the gap between models.

Leaderboard rows are the weakest evidence, so start there. The Terminal-Bench differences are 3 to 8 points with error bars around 1.2 points: real, but modest.1 Older numbers point the same way. Anthropic reported Claude 3.7 Sonnet at 63.7% on SWE-bench Verified in a plain setup and 70.3% once it added parallel attempts, regression-test filtering and a ranking model.2 An aggregator tracking SWE-bench Pro shows Claude Opus 4.5 at 45.89% under a SWE-agent scaffold and 51.80% under Auggie CLI.3

The controlled studies are where the case gets strong. Sydney Lewis froze a model and changed one harness behavior: how old tool results get truncated as the context window fills. On 169 tight-window SWE-bench Verified tasks, the fail-to-pass rate went from 28% to 49% and complete solutions from 43 to 72.4 An audit of 254 SWE-bench submissions found a within-model scaffold effect of 29.8 points against a model effect of only 8.8 points across the top 30, where no adjacent pair could be separated at α=0.05.5 On GAIA, scaffold choice alone moved one model's accuracy by up to 28 points.6 Zhang and colleagues call this the Binding Constraint Thesis: harness variance can exceed model variance, sometimes enough to reverse model rankings.7

Naming the thing

Birgitta Böckeler put it as an equation: Agent = Model + Harness, where the harness is everything except the model.8 She splits it into concentric layers. The inner harness is what the vendor ships: system prompt, retrieval, orchestration. The outer harness is what you add: instruction files, MCP servers, scripts.

The practice got its name two months earlier. Mitchell Hashimoto described it as a habit rather than a formula, fixed either in an AGENTS.md file or in a real tool like a screenshot script or a filtered test runner.9

“Anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again.”— Mitchell Hashimoto (2026)

Credit is messier than either post suggests. Hashimoto never writes the equation. The encyclopedia entry credits it to Böckeler, notes that the UK AI Security Institute voiced a similar idea in 2023, and lists "agent scaffolding" as the older synonym.10 The components it names are the ones this book covers: tool dispatch, memory and state, a sandbox, context management, guardrails.

Vendors and researchers now define it the same way. OpenAI calls the harness "the layer between your application and the model," responsible for conversation state, tool use, approval policy, failure handling and progress reporting.11 A source-code study of 11 production coding harnesses found seven subsystems and 29 recurring patterns.12 OpenAI also ran the extreme version: a product of roughly a million lines, built in about five months with no hand-written source, where engineers steered through pull requests and CI.13 Reporting on it, Martin Fowler summed up the scope: "Harness includes context engineering, architectural constraints, and garbage collection."13

A short history of the loop

Every harness still runs the same loop from 2022. What changed was everything around it.

ReAct gave the loop its shape: reason, act, observe the result, repeat. Interleaving thought with tool calls beat prior methods by 34 points on ALFWorld and 10 on WebShop.14 In 2023 AutoGPT took that loop and let it run unattended. It showed the appetite was enormous; the repository sits at 187.7k stars.15 It also showed that a loop with no verification and no environment design is a demo, not a worker.

The next step moved the effort from the prompt to the interface. In March 2024 Devin shipped a shell, an editor and a browser inside a sandbox and posted 13.86% on SWE-bench against a prior best of 1.96%. Cognition noted that even when handed the exact files to edit, the best earlier models resolved only 4.80%.16 Two months later SWE-agent named the lever. Its authors coined "agent-computer interface" and reached 12.5% pass@1 by redesigning the commands and feedback the model sees, not the model.17

Anthropic's late-2024 guidance turned that into design rules: separate workflows (predefined code paths) from agents (models directing their own process), shape tools so mistakes are hard to make, and start with direct API calls before reaching for a framework.18 Production systems took the advice. None of the 11 harnesses in the source-code study imports a general-purpose agent framework.12 Then the harness became the product. Claude Code ships with instruction files, hooks and verification loops as first-class features,19 and OpenAI now pitches Codex as an open harness that others build on.11

Prompt, context, harness

Each discipline in this lineage widened what the engineer controls, and the last step crossed from advice to enforcement.

Prompt engineering tuned words. Context engineering, in Anthropic's framing, is its "natural progression": the question becomes what configuration of context is most likely to produce the behavior you want, given that a model has a finite attention budget to spend across every token in the window.22

Harness engineering is about what sits outside the window: tools, hooks, evaluators, resets, sandboxes. The Claude Code documentation draws the line that matters most. It calls the context window "the most important resource to manage," treats instruction files like CLAUDE.md as advisory, and describes hooks as "deterministic and guarantee the action happens."19 An instruction asks the model to behave. A hook makes the behavior happen whether the model complies or not. That gap between advisory and deterministic is the hinge between context engineering and harness engineering.

Böckeler's test for a good outer harness follows from it: raise the odds the agent gets it right the first time, and give it feedback loops to correct itself before a human ever reviews the work.8

Field noteIf the agent breaks the same instruction twice, stop rewording it. Move the rule out of the instruction file and into something that runs: a hook, a test, a linter, or a tool that rejects the bad input.

Why the money cares

Most agent and generative AI projects fail to pay off, and the reasons named are about integration, not intelligence.

Gartner predicted in June 2025 that more than 40% of agentic AI projects will be cancelled by the end of 2027, citing cost, unclear value and weak risk controls.23 Gartner analyst Verma described most current projects as early experiments "mostly driven by hype." In a poll of 3,412 respondents, 19% had made significant agent investments, 42% conservative ones and 31% were waiting. Gartner counted only about 130 genuine agent vendors among thousands claiming the label, and called the rest "agent washing."23

A separate study measures a different population. MIT NANDA's August 2025 report found about 95% of enterprise generative AI pilots showed no measurable P&L impact, based on 150 interviews, 350 surveys and 300 public deployments.24 That figure covers generative AI pilots broadly, not agents, so it should not be quoted as an agent failure rate. Its diagnosis is the useful part: the cause was a "learning gap" and poor integration into workflows, not model quality. Bought tools succeeded about 67% of the time; internal builds about 33%.24

Read together, both reports point at the layer this book is about. The harness is the integration: what the system remembers, what it is allowed to touch, how it checks its own work. It is also where the cost goes. Anthropic's planner, generator and evaluator setup cost about $200 and six hours against $9 and twenty minutes for a solo agent, for output it called dramatically better.21 That spend buys the harness, not a better model.

The people who build the outer harness

If integration is where projects die, someone has to do the integrating. The industry's answer is a job title Palantir pioneered in the early 2010s: the forward deployed engineer.25 Palantir's own description of the role is blunt. Its job is to “ensure the solutions we build actually work,” and in a world of demo-ware to deliver “tangible outcomes.”26 The model labs now hire for the same seat. OpenAI's FDEs “lead complex end-to-end deployments of frontier models in production” and are measured on “eval-driven feedback that changes product and model roadmaps.”27 Anthropic's embed with customers to deliver “MCP servers, sub-agents, and agent skills.”28 Read in this book's terms, that is a job description for building the outer harness by hand: the customer's context, tools, guardrails and evals. Reported FDE job postings grew more than 800% between January and September 2025.25

The leverage runs in both directions. The customer gets a harness fitted to their data and workflows. The vendor gets something no benchmark provides: field failures, which become evals and repeatable patterns, and those flow back into the inner harness everyone else uses.28 Investors have called the trade “margin for moat,” accepting services-heavy margins today to become the system of record tomorrow.29 Critics, including Palantir veterans, warn that most copies of the role reproduce its form without its function, and that it degrades into consulting with a new title when customer fixes never reach the product.3031

Hint · forward deployed engineeringThe test that separates an FDE from a consultant is the one this book applies to every harness fix: does the lesson from the field become a reusable artifact, such as an eval, a tool, a skill or a guardrail, or does it die in one customer's repo? Every bespoke harness an FDE builds is a draft of the next product feature.

Built to be deleted

Every piece of a harness is a bet against a specific model weakness, which is why good harnesses are designed to shrink.

“Every component in a harness encodes an assumption about what the model can't do on its own, and those assumptions are worth stress testing.”— Prithvi Rajasekaran, Anthropic (2026)

The examples are concrete. Agents asked to grade their own output tend to praise it even when it is mediocre, so Anthropic split the evaluator from the generator.21 Long-running agents lose state across context resets, declare victory early and leave broken environments behind, so the fix was an initializer agent, a feature list, a progress file and a fixed startup routine.20 Each of those is scaffolding around a known gap. When the gap closes, the scaffolding should go. The catch, in Rajasekaran's words, is that the space of useful harness designs "doesn't shrink as models improve. Instead, it moves."21

That is the frame for the rest of this book. A harness has five subsystems, each built around a different model limitation, and each gets a chapter:

  1. The Loop: how the agent decides, acts and knows when to stop.
  2. Context: what the model sees, and what you leave out.
  3. Tools & Environment: the interface the model acts through.
  4. Guardrails & Trust: what it is allowed to do, enforced rather than requested.
  5. Evals & Evolution: how you know the harness helps, and when to remove a piece.

Start with the loop. Everything else hangs off it.
