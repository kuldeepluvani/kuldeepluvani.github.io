The Harness · Chapter 1

The Loop

Every agent is a loop of observe, plan, act and verify. The hard parts are when it stops, when to run more than one, and how it survives a restart.

~10 MIN READ1 LIVE INSTRUMENT

The agent class in mini-swe-agent is about 100 lines of Python. It has one tool, bash. Every step appends to a single list of messages and nothing is ever removed. With a strong model behind it, that loop resolves more than 74% of SWE-bench Verified.1 Whatever you picture when you hear the word agent, the working core is smaller than that.

A loop is all it is

Strip any coding agent down and you find the same shape: call the model, run the tool it asked for, append the result, call it again. The model does the thinking. Everything else, from which tools exist to what the model sees next turn to when it stops being called, belongs to the harness.

Claude Code's documentation names three phases, gather context, take action and verify results, and says they blend together. It also says the layer around the model that supplies tools and manages context is what the term agentic harness refers to.2 This chapter draws the same ring with four stops: observe, plan, act, verify. Plan is the phase that tends to hide inside the model's reasoning. Verify is the one that tends to go missing.

The interesting engineering sits at the edges of the loop, not in the middle. What goes into the context each turn is chapter 2. What the tools look like is chapter 3. This chapter is about the loop itself: where it came from, when it should stop, when to run several, and how it survives being shut down.

Where the loop came from

Every phase in that ring was a paper before it was a product feature.

ReAct (2022) interleaved reasoning traces with actions and observations. The authors argued that reasoning helps a model track and revise its plan, while actions let it reach outside sources. With one or two in-context examples it beat imitation and reinforcement-learning baselines by an absolute 34 points on ALFWorld and 10 on WebShop.3

Reflexion (2023) added the verify step. The agent receives a feedback signal, writes a reflection in plain text, keeps it in an episodic memory buffer and tries again. That reached 91% pass@1 on HumanEval against GPT-4's 80%.4 Tree of Thoughts (2023) added planning in the strong sense: several candidate paths, lookahead, backtracking. On the Game of 24 it took GPT-4 from 4% with chain-of-thought to 74%.5

Then the field learned how much the loop's surroundings matter. SWE-bench put 2,294 real GitHub issues in front of models, and Claude 2 resolved 1.96%.6 SWE-agent changed the interface instead of the model, designing commands, file viewers and error feedback for what its authors called a new category of end user, and reached 12.5%.7 Today a 100-line bash loop clears 74% on the Verified subset, with much stronger models doing the heavy lifting.1 The harness is a variable, and for a stretch it was the variable that moved fastest.

“Looks done” is not a stop signal

Anthropic's widely cited taxonomy separates workflows, where LLMs and tools run through predefined code paths, from agents, where the model directs its own process and tool use.8 It lists five workflow patterns (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) and reserves agents for open-ended problems where the number of steps cannot be predicted. The price is latency, cost and compounding errors, which is why the same post recommends stopping conditions such as an iteration cap.8

Google's ADK makes the exits explicit. Its LoopAgent ends when it hits max_iterations or when a sub-agent sets escalate to true, and the docs' writer, critic and refiner example caps at five passes.9 Budget and escalation: every loop needs both.

The default exit in a coding agent is quieter and worse. The model stops when it believes it has finished. Claude Code's best-practices guide says so directly.

“Without a check it can run, ‘looks done’ is the only signal available, and you become the verification loop.”— Claude Code best practices, Anthropic

The guide lays out four escalating gates: a check written into the prompt, a /goal evaluator, a Stop hook that acts as a deterministic gate, and a verification subagent.10 A Stop hook can return a JSON decision of block with a reason, or exit with code 2, and the model keeps working with that reason in front of it. Its input carries a stop_hook_active flag so the hook itself can avoid looping forever.11 Even compaction has a breaker: if the context refills right after each summary, Claude Code gives up after a few attempts and shows an error.2

Ralph: the dumbest loop that works

Geoffrey Huntley's Ralph technique is one line of shell: while :; do cat PROMPT.md | claude-code ; done.12 The same prompt, forever, against a repository that changes underneath it. Each pass reads the files, does one thing, and exits. His rule is one item per loop.

“That's the beauty of Ralph - the technique is deterministically bad in an undeterministic world.”— Geoffrey Huntley (2025)

When Ralph does something dumb, you do not swap the model. You add a sign to the prompt, the way a playground gets a sign telling kids to slide down instead of jumping. Huntley reports delivering an MVP on a $50k contract for $297, and he used the method to build a compiler for an esoteric language called CURSED.12 Those are one practitioner's numbers. The mechanism holds regardless: a deterministic outer loop around a nondeterministic worker, with all state kept on disk.

Anthropic's ralph-wiggum plugin moves the loop inside the session with a Stop hook. You start it with a prompt, --max-iterations and --completion-promise. The prompt never changes, and the agent improves by reading its own past work in files. The hook blocks every stop until the output contains the exact promise string inside <promise> tags or the count reaches the cap, and its system message reminds the agent not to claim completion falsely. The README tells you to rely on --max-iterations as the primary safety mechanism.13 In the Ralph panel above, drag the cap below the iteration where the promise lands: the loop stops, the spend is fixed, and the work is unfinished. That is the correct failure.

Fan-out, and its critics

Once one loop works, the obvious move is to run several. Anthropic's research system has a lead agent that plans and delegates to subagents running in parallel. With Opus 4 leading Sonnet 4 workers, it beat single-agent Opus 4 by 90.2% on an internal research eval. Token usage alone explained 80% of the performance variance on BrowseComp, the system uses about 15 times the tokens of a chat, and parallel tool calls cut research time by up to 90%.14 Its prompts scale effort to the query: one agent and 3 to 10 tool calls for a fact, 2 to 4 subagents for a comparison, more than 10 for complex research.14

Cognition's Walden Yan argued the opposite the same month: share full context and full agent traces, not just individual messages.15

“Actions carry implicit decisions, and conflicting decisions carry bad results.”— Walden Yan, Cognition (2025)

His example is a Flappy Bird clone split between two subagents that return a background and a bird in mismatched styles.15 A Berkeley study of more than 1,600 multi-agent traces across seven frameworks found 14 failure modes in three categories: system design, inter-agent misalignment, and task verification.16 Verification shows up again.

The two positions reconcile once you look at what each side parallelizes. Research is reads. Subagents search, condense and report back, which Anthropic's context-engineering guidance frames as a clean separation between search and synthesis.17 Code is writes, and two writers with different assumptions collide. Claude Code keeps subagents in separate context windows that return summaries, recommends a fresh-context reviewer that will not be biased toward code it just wrote, and gives parallel writers their own git worktrees.10 Cursor 2.0 runs up to eight agents on one prompt the same way, isolated on worktrees or remote machines.18

Field noteParallelize reads, serialize writes. Fan out for search, review and investigation. When two agents must change code, give each its own worktree and merge through a single point that runs the tests.

Surviving the session boundary

Long tasks outlive a context window, and each new session begins with no memory of the last.19 Anthropic's harness for long-running agents treats that as a handoff problem. An initializer agent writes an init.sh, a progress file and the first commit. Every later session is a coding agent that builds one feature against a JSON list of 200-plus features, each marked pass or fail. Each session opens with the same ritual: read the progress log, check git history, run the basic tests, pick the next failing feature.19

Drop the ritual and the failures are predictable: declaring the project done early, leaving bugs and undocumented changes behind, marking features passed without testing them, and spending tokens rediscovering state.19 Two of those four are verification failures.

Cloud agents face a harder version, where the gap is a CI run or a human review that takes hours. Cognition found containers cannot survive those gaps and now snapshots memory, process trees and filesystem at the hypervisor level so a task can stop and resume.20 OpenAI's Codex cloud gives each task its own workspace and hands back diffs, logs and test results with citations, not a claim that it worked.21 Claude Code stores sessions as JSONL that can be resumed or forked, but sessions are independent.2 Anything that must carry over belongs in files.

What it costs

The loop is free. A while statement costs nothing. What costs money is each pass through the model, and what costs trust is each pass that ends without a check.

Anthropic's research numbers give the shape: tokens explain most of the quality, fan-out multiplies tokens roughly fifteenfold, and parallelism buys back time, not money.14 Agentic systems trade latency and cost for task performance by design.8 Model speed is a loop-level lever too; Cursor pitches its Composer model as 4x faster than similarly intelligent models.18 And a cap is a budget. Maximum iterations times tokens per iteration is the most a loop can spend, which is why the Ralph panel multiplies them.

So keep the loop simple, cap it, and spend on verification: the test run, the fresh reviewer, the Stop hook that refuses “looks done.” Every turn of the loop also feeds the model a context window, and that window is usually the first thing to degrade. That is Chapter 2.
