The Harness · Chapter 2

Context

The window on the spec sheet is not the window the model can use. The harness decides, every turn, which tokens earn a place in it.

~9 MIN READ1 LIVE INSTRUMENT

Give Claude 3.5 Sonnet a short passage and a question whose answer shares no keywords with it, and it finds the answer 87.5% of the time. Pad the passage out to 32K tokens, a quarter of the 128K the model was built to accept, and the score falls to 29.8%.1 The task did not change. Only the amount of text around it did. The gap between what a window can hold and what a model can actually use is the subject of this chapter, and managing that gap is most of what a harness does.

The job is context, not prompts

In mid-2025 several groups settled on the same name for this work within weeks of each other. Karpathy called it the art and science of filling the window with just the right information for the next step, and warned that too much, or the wrong kind, raises cost and lowers quality.2,3 Cognition put context engineering at the core of agent reliability.4 Manus published the lessons of building its agent around it.5 Anthropic defined it as curating and maintaining the best set of tokens during inference, with prompt writing as one subset of the job.6

The rename matters because it moves the unit of work. A prompt is written once. Context is assembled on every turn of the loop from Chapter 1: instructions, tool definitions, files, earlier tool results, the model's own previous output. Anthropic's documentation describes the harness itself as the layer that supplies tools and manages what the model sees.7 A prompt is a sentence. Context engineering is a policy that runs fifty times per task.

The advertised window is not the usable window

Every serious long-context benchmark finds the same thing: accuracy falls well before the limit on the spec sheet, and often by 8K to 32K tokens.

RULER tested 17 models on 13 tasks. All claimed at least 32K of context; only about half held up at 32K.8 NoLiMa removed literal word overlap between question and answer, so the model had to make a one-step association instead of string matching. At 32K, 11 of the 13 models it tested scored below half their short-context baseline.1 A Databricks study ran 20 models from 2K to 128K in a retrieval setting and found that only a handful of the newest stayed consistent past 64K; the rest failed in their own ways, from refusals to dropped instructions.9 Chroma's study of 18 models, GPT-4.1, Claude 4 and Gemini 2.5 among them, saw decline with length even on copying a run of repeated words. On LongMemEval, a focused prompt of about 300 tokens beat the full one of roughly 113K.10

Position matters as much as length. Lost in the Middle gave the curve its shape: with 20 documents, GPT-3.5-Turbo answered correctly 75.8% of the time when the relevant document came first, 53.8% when it sat tenth, and 63.2% when it came last. With no documents at all it scored 56.1%.11 Burying the answer in the middle made the model slightly worse than giving it nothing.

Anthropic frames the cause as an attention budget. Every token attends to every other, so relationships grow with the square of length, and training data skews toward short sequences.6 Chroma named the symptom: context rot.10 The gauge below plots NoLiMa's numbers. Four ways context fails

Drew Breunig sorted long-context failures into four kinds.12 The taxonomy is useful because each one has a different fix, and applying the wrong one wastes a week.

ModeWhat happensEvidenceFix
PoisoningA hallucination or bad result enters context and is re-read as fact on every later turnBreunig's definition; no single benchmarkPrune it or restart
DistractionHistory grows until the model copies past actions instead of planningGemini 2.5 agent past ~100K tokensCompact
ConfusionIrrelevant material, often tools, pulls the model off taskLlama 3.1 8B: fails with 46 tools, passes with 19Fewer tools, loaded on demand
ClashParts of the context disagree with each otherSharded prompts: average −39%; o3 98.1 → 64.1Quarantine exploration

Clash deserves attention because it is the one harnesses cause. In the sharded-prompt study Breunig cites, splitting the same task's information across several turns cost 39% on average.12 An agent that writes exploratory drafts into its main thread is manufacturing clash.

Budget it like RAM

Karpathy's framing holds up: the model is the CPU and the context window is RAM.3 MemGPT made the analogy literal, with a main context the model reads directly and an external store it pages data in from.13 The practical consequence is to split cost into two lines: fixed overhead and per-step spend.

Fixed overhead is everything loaded before the user types. In Claude Code that means the system prompt, CLAUDE.md, the first 200 lines or 25KB of auto memory, MCP tool names and skill descriptions, with full MCP tool definitions deferred until used.14,7 Each of those tokens is paid on every turn of every session. Per-step spend is file reads, tool output and the model's own reasoning.

Progressive disclosure keeps overhead small. Agent Skills load in three levels: name and description up front, the body only when relevant, bundled files only when read.15 The same discipline applies to instruction files. Anthropic's test for each line of CLAUDE.md is whether deleting it would cause mistakes; bloated files make the model ignore the instructions that matter.16

When spend does pile up, cut in order of cost. Claude Code clears older tool outputs first and summarizes only if that is not enough.7 At the API level, tool-result clearing triggers at 100,000 input tokens by default and keeps the last three tool uses.17 Anthropic measured context editing alone at +29% on an agentic search eval, +39% with a memory tool added, and 84% fewer tokens over a 100-turn web search run.18 As of June 2025 Claude Code auto-compacted at 95% of the window.3

Compaction is lossy, so decide what survives it. After compacting, Claude Code re-reads up to five recently modified files (larger ones come back as paths), re-injects skill bodies capped at 5,000 tokens each and 25,000 in total, and reloads CLAUDE.md and memory from disk. Nested instruction files and path-scoped rules are summarized away.14 Anthropic's advice for writing a summarizer is to tune for recall first, then precision, keeping decisions, open bugs and implementation details.6

Field noteWrite down your compaction contract: the five things that must survive a summary (goal, decisions, open bugs, files touched, next step). Then force a compaction halfway through a real task and check the agent can name all five. If it cannot, the contract lives in a file, not in the transcript.

Move it out, pull it in

The filesystem is the cheapest memory tier because it is restorable. The lightest version is a notes file the agent writes and rereads.6 Manus has its agent rewrite a todo list every step, which pushes the goals to the recent end of context across tasks that average about 50 tool calls. It treats files as unlimited, persistent and directly operable, and compresses only in ways it can undo: keep the URL, drop the page.5

Heavier systems formalize the tiers. Letta splits memory into core blocks the agent edits in context, searchable recall history, and an archival store, and on overflow evicts about 70% of messages behind a recursive summary.19 Mem0 extracts and consolidates facts; on the LOCOMO benchmark it reported a 26% judge-score gain over OpenAI's memory, 91% lower p95 latency and over 90% fewer tokens than replaying full history.20

Case study · a memory that argues with itself

Every memory tier above shares a weakness: whatever gets written is believed. A wrong fact stored once is retrieved forever, which is context poisoning made permanent. Mycelium, one of my own projects, explores the opposite design: memory that has to earn its way in.

  1. Perceive in layers. A cheap structural pass reads the shape of each source before a deeper pass extracts entities, relationships and claims, so expensive reasoning is spent only on what structure cannot answer.
  2. Challenge before storing. An adversarial pass disputes every extracted claim, and a consistency check tests it against what is already known. Only reconciled facts enter, each carrying a confidence score and its provenance.
  3. Forget on purpose. Confidence decays unless new evidence reinforces it, and duplicates merge, so the store tends toward what is still true rather than everything ever said.
  4. Let structure create specialists. Dense clusters in the knowledge graph each become a specialist agent with a deep, narrow context, so no single window has to hold everything.
  5. Route, don't stuff. A supervising tier decides which specialists a question needs and pulls only their answers into the final context. This is the chapter's pull-not-push principle applied to memory itself.

The design bet is that memory quality is a verification problem, not a storage problem. That is the same lesson Chapter 5 draws for evals.

Retrieval has the same push-or-pull choice.

“Claude Code doesn't use RAG currently. In our testing we found that agentic search out-performed RAG for the kinds of things people use Code for.”— Boris Cherny, Hacker News (2025)

Anthropic calls the pattern just-in-time context: hold lightweight identifiers such as paths, URLs and queries, and load the content only when a step needs it, with upfront retrieval kept for cases where speed matters.6

Subagents push the same idea further by spending tokens in a separate window. Anthropic's research system uses about 15 times the tokens of a chat, and token usage alone explained 80% of the variance in its BrowseComp results.21 Each subagent hands back a condensed summary of 1,000 to 2,000 tokens.6 The limit is decisions.

“Actions carry implicit decisions, and conflicting decisions carry bad results.”— Walden Yan, Cognition (2025)

Parallel workers that never see each other's traces make incompatible choices. Cognition's Flappy Bird example shows subagents building parts that rest on conflicting assumptions. Read-only investigators that report back to one decision-making thread are the safe form.4

Pay attention to the cache

The cheapest token is one already sitting in the KV cache.

“the single most important metric for a production-stage AI agent”— Yichao “Peak” Ji, Manus, on KV-cache hit rate (2025)

Agent loops read far more than they write. Manus reports input-to-output ratios around 100:1, so the input price dominates the bill.5 For Sonnet 4.5 input costs $3 per million tokens, a cache read $0.30, a five-minute cache write $3.75, and output $15.22 The cache matches on prefix in the order tools, then system, then messages, and any change invalidates everything after it. Sonnet 4.5 needs at least 1,024 tokens to cache at all.22

That makes cache discipline an architecture rule, not a style preference. Keep timestamps out of the system prompt, append instead of editing history, serialize deterministically, and mask tools rather than removing their definitions mid-session.5 It also explains a tension from Section 4: clearing old tool results breaks the cached prefix, which is why the API lets you require a minimum amount cleared per edit so the rewrite pays for itself.17

Run the numbers and the shape is clear. A cache miss is billed as a write at 1.25× the base input price,22 so hit rates below about 22% lose money. Past that point the 10× read discount dominates, and with output a hundredth of input, the session cost follows the hit rate almost exactly.

What fills the window next

The pattern across this chapter is that a long context is a liability you manage, not a resource you fill. Keep fixed overhead small, cut stale results before summarizing, put durable state in files, pull content in on demand, and protect the cached prefix.

Most of the per-step spend, though, is tool output: file reads, search hits, command logs. How much of it lands in the window depends on what tools the agent has, how they are described and what they return. That is Chapter 3.
